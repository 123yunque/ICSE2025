# MBPP+ 粒度三本地流水线准入与三输入实验报告

## 1. 实验设置

- 数据集：标准化 MBPP+，共378个任务。
- 输入：每个受支持任务按 `code_inputs.txt` 顺序选择前3个输入。
- 执行隔离：每个 `(task, input)` 使用独立Python子进程。
- 初始超时：5秒；超时样本使用15秒低并发复核。
- 动态事件上限：10,000。
- 单样本输出上限：20MB。
- 运行时动态轨迹预算：5MB，在完整产物膨胀前提前终止。
- 辅助函数口径：目标函数内部完整追踪；辅助函数调用暂时作为原子操作。

## 2. 静态准入结果

| 状态 | 任务数 |
|---|---:|
| supported | 369 |
| unsupported_recursion | 6 |
| unsupported_jump | 3 |
| 合计 | 378 |

目标函数支持率：`369/378 = 97.62%`。

排除任务：

- 直接递归：task_65、task_103、task_297、task_389、task_462、task_583；
- break/continue：task_123、task_278、task_622。

早期粗粒度审计得到366个安全任务；本轮通过任务元数据中的测试断言准确解析入口函数后，确认另外3个
递归/生成器结构仅存在于辅助函数，不在目标入口函数中。按照“辅助调用原子化”的当前实验口径，这3个
任务可以准入，因此最终支持数为369。

## 3. 三输入执行结果

| 指标 | 数值 |
|---|---:|
| 计划执行样本 | 1107 |
| 成功样本 | 1106 |
| 规模超限样本 | 1 |
| 成功率 | 99.91% |
| 生成动态事件 | 8534 |
| 生成模型Probe | 8534 |

唯一排除样本：

```text
task_67/original/input_3
input = (56,)
function = bell_number
reason = TraceSizeLimitExceeded
observed = 5,027,782 bytes > 5,000,000-byte trace budget
```

该程序维护 `57×57` 的二维动态规划矩阵。若每个动态事件均重复保存完整执行前后状态，产物会膨胀至
约533MB。因此该样本按既定输出规模标准排除，不能简单放宽超时继续生成。

## 4. 超时复核

初始8路并发、5秒预算下有两个超时：

- `task_247/input_3`：15秒低并发复核成功；实际执行约1.86秒，1137个事件，完整产物约16.5MB；
- `task_67/input_3`：增加运行时轨迹预算后约1秒内确定为规模超限。

因此最终没有未解释的超时、进程崩溃或事件上限失败。

1106套有效产物共约37.89MB，最大单样本约16.50MB。

## 6. 完整性验证

对1106个成功样本逐一验证：

- `case.json/cfg.json/events.jsonl` SHA-256；
- JSON/JSONL可解析性；
- `event_count = model_input_count = answer_count`；
- 模型输入和本地答案的 `probe_id` 顺序一致；
- `model_inputs.jsonl` 不包含 `next/delta/return/state_after` 等答案字段；
- `answers.jsonl` 独立保存。

验证结果：

```text
valid = 1106
invalid = 0
valid events = 8534
```

## 7. 结论

当前实现已经适合在明确的 Python 支持子集上进行全数据集批量生成。对 MBPP+ 的目标函数覆盖率为
97.62%，在受支持任务的前三个输入上，本地Oracle生成成功率为99.91%，所有成功产物均通过完整性和
答案隔离检查。

当前结果还不能代表跨函数内部过程、递归、break/continue和超大状态程序。后续优先扩展多frame和跳转
控制流；对于超大动态状态，应采用状态patch、动态切片或循环压缩，而非取消输出限制。
